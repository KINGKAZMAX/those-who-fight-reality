# 校园像素美术与 Mac 双人操作验收

日期：2026-10-17。对象：《与名为现实的怪物战斗的人们》当前本地试玩。

## 本次交付

- 9 张生成运行图片：4 位伙伴、纸卷怪、3 处校园背景、1 张道具与特效表。
- 主菜单、选角、战斗 HUD、设置、暂停与结算均已换为蓝色校园像素风。
- 默认双人同队。玩家一 WASD + F/G/H；玩家二方向键 + J/K/L；P 暂停，Esc 退出。
- 有效改键立即保存；重复按键和保留快捷键会提示；可恢复推荐方案；已有自定义设置保留。

## 实机验收结果

使用本机 Chromium 的独立测试配置，不清空或覆盖用户浏览器设置。桌面视口 1280×900，小视口 700×600。以下均已通过：

| 检查 | 结果 |
| --- | --- |
| 主菜单 → 设置 → 保存返回 → 键盘选角 | D 可将玩家一从小一切换到林夏 |
| 按键冲突 | 将玩家一攻击改成 J 时提示「J 已用于玩家 2 的攻击」 |
| 改键保存 | F 改成 R 后刷新仍为 R；恢复推荐后回到 F |
| 同时移动 | 同时按 A 与 →，两位玩家 x 从 250/550 变为 175/625 |
| 同时跳跃 | 同时按 G 与 K，两人均进入跳跃帧，y≈−43.8 |
| 同时防御与攻击 | H/L 同时进入防御帧；F/J 同时进入攻击帧 |
| 暂停与返回 | 长按 P 只暂停一次，游戏计时停止；再按恢复；Esc 回到选角 |
| 三个场景 | 小学、初中、大学均能进入实际对战；四位伙伴均已上场 |
| 8 人同屏 | 初中场景 2 位玩家 + 6 只怪物；连续 8 秒每秒采样均为 30 FPS |
| 命中 → 击倒 → 结算 → 返回 | 真实 F 攻击造成 20 点伤害，击倒目标并出现结算，返回按钮可重新选角 |
| 演示入口 | `?demo` 使用现有场景，正常进入战斗 |
| 资源与异常 | 全流程未记录页面运行异常或失败资源响应；提供的游戏测试客户端也正常退出 |

同时按键检查为避免敌人干扰，在测试浏览器内临时固定站位并停用该目标 AI；击倒检查临时将敌人 HP 设为 1，再由真实按键攻击触发伤害、死亡和结算，未直接调用结算界面。三场景和帧率采样使用正常 AI。这些测试设置不写入游戏源文件。

键盘事件由浏览器自动化发送，已验证软件对同时按键的处理；没有进行两位真人在实体键盘上的长时间试玩。短时帧率采样不代表所有 Mac 或长时间场景的性能保证。保持上游 30 FPS 逻辑，无倍速调整。

## 可重复检查

- `node --test tests/mac-controls.test.cjs tests/manager-demo.test.cjs`：9 项通过，覆盖默认键位迁移、旧自定义保留、冲突、物理按键码、失焦释放、长按与演示场景。
- `node tools/check_reality_art.cjs`：通过，检查 9 张资源、65 张适配图集、3459 个映射格、原动作和碰撞数据、背景比例与边界。
- `node tools/verify_reality_browser.cjs`：全流程通过，原始结果见 [reality-browser-report.json](reality-browser-report.json)。脚本默认使用本机 Codex web-game 技能附带的 Playwright，也可用 `PLAYWRIGHT_MODULE` 指定模块路径。
- 所有本轮修改的 JS 均通过语法检查；按 develop-web-game 技能提供的客户端完成开局及双人移动检查，输出位于 `reality-client/`。

验收中修复了旧版 RequireJS 不接受 async 工厂回调导致加载停滞、从首页设置返回未初始化选角控制器、战斗底栏遮住场景、演示入口选择不存在背景四处问题。

## 当前范围

这是一版合作对战美术试玩。每角色源表为 16 个独立姿态，复用上游动作时间线；65 张图集 / 3459 个格子不是同等数量的独立动画。完整升学剧情、考试系统、章节首领、年龄成长和援护机制尚未实装。动作判定与音频仍继承 F.LF / LF2。未完成手机、联网、音频及长期压力测试。
